# 听唐渡梦发布与运维流程

生效日期：2026-10-14。流程身份：TTDM_RELEASE_FLOW_20261014_V2。

这是当前唯一执行流程，替换旧版流程正文。历史 Git 提交、已发布版本清单和原始验收回执仅作追溯，不作为当前派工指令。当前版本和实际进度见 `handoff/CURRENT_RELEASE.md` 与相应部署回执。

## 1. 分工与来源

Codex 在本机定位、修复、验证，先将同版服务端和客户端晋升至 `J:/单机整合/听唐渡梦单机`，完成正式根实际验收。验收后从冷态正式根直接取文件生成逐文件清单及本地完整快照，再提取相对上一已发布版的增量。禁止从另一候选或旧包临时拼成发行程序，防止漏修复或回退。

WorkBuddy 只负责云端成品部署、环境配置、备份、服务启停、托管、重打包及回执；不改游戏源码、不编译、不更改业务程序、资源、版号、默认分辨率或更新通知。Codex 不登录或操作云服务器。

## 2. 每版交付形式

- 常规更新向 GitHub 公共成品仓库上传**增量更新包**，不重复上传完整服务端和客户端。首个基线、全新环境或用户另行要求时才交完整包。
- 同版完整源码仍每版上传独立私有源码仓库。公共仓库和 WorkBuddy 交接仅引用源码版本、commit/tree、私有归档位置和校验值，不收游戏完整源码。
- 公共增量必须给出适用基线、目标版、逐文件前后长度与 SHA-256、删除项、完整目标清单、原生更新文件、更新通知、环境配置工具及同版验证记录。
- Codex 保留本地完整快照和准确的正式根来源映射。增量加基线必须能够重建与正式根一致的完整目标。
- 两个必要例外是交付副本的零玩家初始数据库和公共默认设置；本机测试账号、缓存、凭据、聊天/运行日志和存档不进入包。本机实际存档和玩家设置不得因打包清除。

## 3. 网络配置边界

本机正式根与当前隔离工程所有可运行配置、备用模板、服务器下发列表、更新清单和补丁内配置只使用本机地址。交付原包同样保留本机默认配置，不在这些环境内运行公网变体。

WorkBuddy 在云端**全新冷态部署候选**中填写真实公网地址和端口。地址改变由 WorkBuddy 在云端配置，Codex 不把公网配置写回本机正式根。使用同版附带的 `Configure-Deployment.py`，先核完整目标清单；工具只改环境白名单及由它派生的校验值，不改变游戏程序或原生补丁的非环境有效载荷。

| 文件 | 字段或内容 | 配置责任 |
|---|---|---|
| 客户端/听唐渡梦/data/update.ini | ServerList、UpdateURL、NoteFile | 公网 HTTP 地址与更新端口；保留 Version |
| 客户端/听唐渡梦/data/areaserver.xml | ReceptionServer.Address/Port，Socket T/N/E Address/Port | 公网接入地址、接待及注册登录端口 |
| 服务端/config/server.template.json → server.json | listen_address、redirect_address、native_feed_listen_address，rcp_port、gcc_port、redirect_port、native_feed_port | 监听/公网重定向/四类端口 |
| 服务端/update-feed/stable/serverlist.txt | ReceptionServer 与 Socket T/N/E | 必须与完整客户端一致 |
| 服务端/update-feed/stable/patchlist.txt | 各原生补丁 URL | 从云服下载；不能指向 GitHub |
| 所有被引用的 .dt | 其中实际存在的 data/update.ini、data/areaserver.xml | 与完整客户端同环境；其余载荷和版本保持 |
| update-feed/feed-manifest.tsv 与 runtime-manifest*.json | 派生长度、SHA-256 | 配置后重新核算 |

当前默认端口：接待 6666、注册登录 10003、世界 12000、更新 HTTP 18080。公网端口变更时必须同时检查客户端、服务端广告地址、更新清单及防火墙/安全组。

`session_key_hex`、`redirect_key`、`gas_server_seed` 只在云端注入，不回传秘密。GAS seed 为 8 位大写十六进制，最后两位必须为 `00`；已验证的既有密钥保留。配置注入后按实际字节更新 runtime manifest 的 config_length/config_sha256。不得把环境变量、占位符或模板直接作为已实例化配置启动。

原始交付 ZIP、已封版本和既有原生补丁保持不可变。环境配置后的文件、完整客户端压缩包与原生补丁记录独立部署身份。更换地址时在新候选/新环境中生成，并核对已托管的同名 URL；禁止静默覆盖旧不可变补丁。

## 4. 版本和更新通知

正式版号为 `v服务端.客户端.数据库`，在最新已发布版上持续累加，按实际变化递增对应段，未变段保留。客户端窗口、原生更新头、data/update.ini、服务端版本声明、完整客户端下载包、更新清单和同版源码必须相互一致。

**每次发布必须更新同版本“更新通知”。** 写明更新日期和本次实际变更，新版在前、旧版保留；先用“一、二、三”分大类，再用“1、2、3”列细项。玩家文案统一使用“服务器”，不写“首次云服”“云服务器”等字样。data/note.txt 与服务器 stable/note.txt、原生补丁中的通知必须一致，编码 CP936、无 BOM、CRLF。用户协议文件保持 0 字节。缺通知、版号不符或内容不是本次更新时不得发布。

客户端默认 1024×768，原生设置程序标题为“听唐渡梦”，提供 800×600、1024×768、1366×800 三档，保存玩家选择。更新不能强制覆盖已有玩家的分辨率。

## 5. 标准升级顺序

1. Codex 完成受影响修复、验证及正式根晋升；正式根实际验收通过。核对原有效证据后复用，不重做无关已闭合项。
2. 从正式根直接生成本地快照及增量，验证“上一版 + 增量 = 本版完整目标”，排除玩家数据；同步本次版号、日期和更新通知。
3. Codex 发布公共增量及同版完整私有源码，完成上传/下载哈希回读，向原 WorkBuddy Issue 单次交接，列清最新实际 first_unfinished。
4. WorkBuddy 校验基线和增量。在全新目录重建完整目标，核逐文件清单，再配置公网地址及端口。不要把原包直接覆盖到正在运行的服务端，也不要用玩家使用过的客户端作为发行基础。
5. 对旧运行根精确核 PID、路径、创建时间及重启任务，冷停并私有备份数据/配置；将需要保留的现有玩家数据迁移到新候选，按数据库规则执行。禁止因完整包自带初始空库就覆盖现有数据。
6. 使用同版服务端与客户端完成受控云端验证。此阶段端口健康仅是前提，不是业务验收。
7. 云服必须同时保存**最新完整客户端**供新玩家下载，以及**原生自动更新文件和必要历史链**供已有玩家启动时更新。WorkBuddy 按获准环境配置重打包最新完整客户端，记录逐文件和压缩包哈希。
8. 实测两条路径：另一电脑从最新完整包注册、登录和进游戏；旧版客户端正常启动，从云服自动更新后登录、检查标题版号及同版更新通知，再次启动无重复更新或版本倒退。含本次受影响业务、多客户端、必要持久化/重启验证。
9. 以上通过后，在同一维护窗口原子切换玩家版本清单、更新文件和最新完整客户端下载入口。不得只更新补丁而保留旧完整包，也不得仅替换完整包却没有自动更新。
10. WorkBuddy 提交带时间、版本、原始包身份、环境差异、部署后成品身份及实际业务结果的回执；Codex 消费并更新台账。用户另一电脑验收按真实结果单列。

本次 v137.119.64 的正式根四项用户验收已通过；本版新原生补丁的云端实际应用和另一电脑验收仍须 WorkBuddy/用户执行，不用上传成功冒充通过。

## 6. 数据保护与唯一清库例外

所有后续更新默认保留云服数据库、账号、角色及存档。没有用户新的明确指令，不得清库、清表、重建、用初始种子或旧备份覆盖现有玩家数据。

唯一当前例外：用户于 2026-10-14 再次明确“此前那次清库继续安排”，只恢复 `INC-2026-10-14-02-ONE-TIME-PLAYER-RESET` 一次动作。先查真实执行回执：已执行则不重复；未执行则在原授权范围核冷停、私有备份、零玩家种子身份、零计数和引用完整性后执行。该授权不延伸到以后版本或另一环境，不与部署重试绑定。原始玩家 DB/WAL/SHM 不上传 GitHub。

程序回退不得覆盖玩家存档；数据库兼容性未明确时不自动回退数据。只暂停受影响动作并回传证据。

## 7. 结果、保留与事故

源码修复、离线验证、正式根通过、GitHub 发布、云部署、外部业务验收分别记录。未运行填 NOT_RUN，未知填 UNKNOWN；每版与问题台账由 Root 维护。

云端完整客户端严格只保留两版：**当前最新版用于玩家下载，紧邻上一版作为回退备份**。新版云端业务验收和下载校验通过后，WorkBuddy 在本次部署收尾直接清理上一版之前的完整客户端压缩包、解压目录及重复客户端备份，不另等下一次更新或再次询问；未验收通过时先保留现有可回退版本。

清理前列明精确绝对路径和对应版本，确认范围仅为旧完整客户端，核当前版及上一版不在清理清单中；清理后提交实际删除路径、时间、释放字节数及剩余客户端清单。验收后若还存在更早完整客户端，部署收尾不得记完成。程序备份同样保留当前和紧邻上一版。

**必要原生自动更新补丁链不等于旧完整客户端。** 仍被更新清单引用、供受支持旧客户端升级所需的补丁必须保留；数据库、玩家存档和必要业务备份独立保护。不得连带删除 GitHub 历史发布、版本台账或原始验收回执。

发现新故障先保护现场和数据，按事件编号在原 Issue 回传脱敏结果。WorkBuddy 不自行修业务源码或重编程序；Codex 使用本机环境复现和修复，下一版本继续以上流程。交接通道：`timliu-joon/ttdm-workbuddy-handoff` Issue #1。
